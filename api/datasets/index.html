Dataset providers¶

A dataset's type picks one of these; its config is the provider's arguments, plus the templates and schemas every provider takes.

Dataset ¶

Dataset(input_data_model=None, input_schema=None, input_template=None, output_data_model=None, output_schema=None, output_template=None, tools_template=None, batch_size=None, limit: int = None, repeat: int = 1, **kwargs)

The engine's streaming Dataset, with every hand-written schema closed at the door.

Everything is the base class': _iter_rows() to implement, the three Jinja2 templates over a row (input_template, output_template and tools_template, the row's own tool declarations as a Chat Completions request carries them, with row_schema the row's shape without them), limit, repeat, batch_size, the (x, y) batches. Two differences. _close_objects: an input_schema or output_schema written by hand is marked closed, object by object, before the base class reads it. And the templates are compiled in the engine's JINJA, as RowTemplates: each sees the whole row as row beside its columns, and has fromjson, fromliteral, as_image and as_audio.

FolderDataset ¶

A folder where each file is one record.

Files are read in name order. A .json, .yaml or .yml file is parsed: a mapping's keys are the record's own fields, any other value is handed over whole as record. UnityCatalogDataset ¶

UnityCatalogDataset(table, *, version=None, as_of=None, storage_path=None, read_batch_size=10000, input_data_model=None, input_schema=None, input_template=None, output_data_model=None, output_schema=None, output_template=None, tools_template=None, batch_size=1, limit: int = None, repeat: int = 1)

A Delta or Parquet table governed by Unity Catalog (Databricks or OSS).

Each row of the table is handed to the templates as a mapping of its columns. The table is found through the catalog's REST API (its storage location, its version token), then read from object storage with deltalake and pyarrow, record batch by record batch, so the table never has to fit in memory. The catalog is reached with UNITY_CATALOG_API_URL and UC_TOKEN; the storage with AWS_ACCESS_KEY_ID, AWS_SECRET_ACCESS_KEY, AWS_DEFAULT_REGION (fr-par unless set) and, for an S3-compatible store, S3_ENDPOINT. What the catalog said of the table is kept in metadata, for the run to record where its rows came from.

Parameters:

Name Type Description Default
table str

The table, fully qualified: catalog.schema.table.

 required
version int

Optional. The Delta version to read. Not with as_of.

 None
as_of str

Optional. The UTC time (ISO 8601) to read the Delta table as of. Not with version.

 None
storage_path str

Optional. Where the table's files are (s3://...), given directly: the catalog is not asked.

 None
read_batch_size int

Rows per record batch read from storage. Defaults to 10,000. Not the run's batch_size.

 10000
